# 本地运行说明

先运行单元测试，再执行演示命令。演示从干净临时目录发起真实请求并处理响应，不需要外部站点。
常规导入失败时返回非零退出码，事务中的原文和记录会一起回滚，可保留源文件再次处理。
查询模式只读取当前数据库，不会补采或删除来源数据。需要长期保留证据时，请备份整个数据库。
本地响应服务支持状态码、响应头、文本或 base64 字节正文；未配置路径返回未找到。
每条路径的脚本独立推进，最后一个响应会重复；可借请求记录核对调用顺序。
数据文件的路径均相对项目根目录，修改工作目录前请确认输入和数据库参数。

## 公示网页语义导入

`.json` 输入走原有单层表导入；其他扩展名（如 `.html`）按公示网页处理，需 `--columns` 指定字段说明。
网页导入先把页面重建为逻辑网格再识别语义列，成功则发布到正式目录并返回 0；
无法确定结构时整页隔离并返回 1：原页已按摘要留存，隔离原因写入批次，不会挪列后继续猜测。
隔离原因代码：`no_table`/`no_header`/`no_data` 结构缺失，`overlap`/`bad_span` 合并单元格非法，
`missing_column` 缺少必需列，`duplicate_column` 语义列重复，`unit_conflict`/`unit_missing` 单位问题，
`blank_cell` 关键单元格为空且无合并覆盖，`invalid_quantity`/`invalid_amount` 数值非法，
`duplicate_key` 页内业务主键冲突，`encoding` 非 UTF-8 页面。

`explain` 对单页输出完整解释（列映射路径、单位来源、跳过的重复表头、隐藏列、记录与坐标），不写库。
`quarantine` 列出当前仍隔离的页面与原因；`replay` 用当前规则重放这些页面。
规则升级（`collector/semantics.py` 的 `RULE_VERSION` 与字段说明）后重放会生成新批次：
已发布数据与原始坐标引用按（主键, 规则版本）保留，目录当前视图取最高版本。
同一页面同一规则版本的导入与并发重放都是幂等的，只会产生一个批次。
服务模式下 `GET /pages`、`GET /quarantine`、`GET /page/<digest>` 供业务人员核对映射与隔离原因。
